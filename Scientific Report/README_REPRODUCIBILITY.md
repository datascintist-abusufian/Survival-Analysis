# Scientific Reports revision — reproducibility guide

## Scope

This directory contains the analysis code and derived outputs for the revised manuscript **“Post-Myocardial-Infarction Survival Modelling: A Reproducible Reassessment Framework.”**

The primary clinical/statistical analyses use the original 132-record UCI Echocardiogram dataset. The survival endpoint is time in months after myocardial infarction; `event=1` denotes death and `event=0` denotes right-censoring/still alive at last follow-up.

Synthetic records are used only in methodological fidelity/augmentation experiments. They are not additional patients and are not external validation observations.

## Canonical data file

The release expects:

```text
outcome/uci_echocardiogram_reconstructed_132.csv
```

Original source: UCI Echocardiogram dataset, DOI `10.24432/C5QW24`.

## Required scripts

The canonical workflow uses:

```text
Scientific_Reports_Reanalysis_Master.py
Real_Data_Core_Reanalysis.py
Nested_FP_Cox_Validation_v1.py
Synthetic_Augmentation_Experiment.py
Synthetic_Bandwidth_Sensitivity.py
Standard_Package_Confirmation_sksurv.py
Generate_Final_Summary_Tables.py
RSF_Permutation_Importance.py
```

Do not substitute older `*_v1.py` or `*_v2.py` files if their contents differ from these release scripts.

## Environment

The manuscript reports Python 3.11.17 with the package versions listed in `requirements_reanalysis.txt`.

Install with:

```bash
python -m pip install -r requirements_reanalysis.txt
```

## Complete release rerun

From inside the `Scientific Report` directory:

```bash
python Scientific_Reports_Reanalysis_Master.py --full-release --outdir rerun_outputs
```

This runs the real-data core analysis, nested FP-Cox validation, primary synthetic experiment, bandwidth sensitivity analysis, final `scikit-survival` confirmation, deterministic final summary-table generation, and final-RSF cross-validated permutation importance.

A lighter core-only rerun is:

```bash
python Scientific_Reports_Reanalysis_Master.py --outdir rerun_outputs
```

The `--full-release` run requires `scikit-survival`.

## Output provenance

### 1. Real-data core

`Real_Data_Core_Reanalysis.py` reproduces the data audit, Kaplan–Meier estimates, Cox PH results, bootstrap optimism correction, proportional-hazards checks, and fractional-polynomial full-sample analyses/figures.

### 2. Nested fractional-polynomial validation

`Nested_FP_Cox_Validation_v1.py` re-selects FP powers inside each training fold and writes the nested FP-Cox validation outputs.

### 3. Final standard-package model comparison

`Standard_Package_Confirmation_sksurv.py` uses the final model specification and the same 25 held-out real folds (repeated 5-fold CV, 5 repeats, seed 42) for Cox PH, nested FP-Cox, RSF, synthetic-only Cox, and real-plus-synthetic Cox.

It writes:

```text
validation_outputs/standard_package_fold_results.csv
validation_outputs/standard_package_model_comparison.csv
```

The RSF specification is:

```text
n_estimators=500
min_samples_split=10
min_samples_leaf=10
max_features='sqrt'
random_state=42 + fold
```

Concordance uses full observed follow-up. IPCW Brier/IBS evaluation uses censoring information from the corresponding real training fold and administrative censoring immediately after 36 months for observations extending beyond the evaluation horizon.

### 4. Final derived reviewer tables

`Generate_Final_Summary_Tables.py` is a deterministic post-processing step. It reads `standard_package_fold_results.csv` and writes:

```text
validation_outputs/final_overall_model_summary.csv
validation_outputs/final_corrected_model_comparison.csv
validation_outputs/paired_fold_model_differences.csv
outcome/cox_rsf_repeated5fold_5repeats.csv
```

The paired-fold table is descriptive only. No inferential p-values are generated from repeated-CV fold differences because those folds are not independent observations.

**Important:** an earlier `cox_rsf_repeated5fold_5repeats.csv` came from a provisional audit. For the DOI release, replace it with the file generated by `Generate_Final_Summary_Tables.py` from the final standard-package fold results.

### 5. RSF permutation importance

`RSF_Permutation_Importance.py` fits the **final** RSF specification on the same repeated-CV design and permutes each predictor within each held-out fold without refitting. It writes:

```text
outcome/rsf_cv_permutation_importance_by_fold.csv
outcome/rsf_cv_permutation_importance.csv
```

`delta_c_index = C(permuted) - C(original)`, so negative values indicate that permutation reduced held-out discrimination.

**Release check:** the previously archived importance CSV was produced during an earlier audit. Run this final-RSF script locally before the DOI freeze. If its numerical range differs from the current manuscript sentence about permutation importance, replace the old CSV and update that sentence to the newly reproduced values.

### 6. Primary synthetic-data experiment

`Synthetic_Augmentation_Experiment.py` implements the smoothed multivariate bootstrap and evaluates synthetic fidelity and held-out-real predictive utility. The generator is fitted only inside real training folds for prediction experiments.

### 7. Synthetic bandwidth sensitivity

`Synthetic_Bandwidth_Sensitivity.py` reproduces bandwidths `0.05`, `0.10`, and `0.20` and writes:

```text
synthetic_bandwidth_sensitivity_summary.csv
```

The release version was checked against the archived sensitivity table and reproduced its numeric contents to floating-point precision.

## Locked-output policy

`locked_results_ledger.json` records the verified revision results. Where an older/provisional output conflicts with the final standard-package confirmation, the **final standard-package result and its generating script take precedence**. Obsolete provisional artifacts should not be retained in the DOI release under ambiguous filenames.

## Pre-release checks

Before creating GitHub release `v1.0.0` and archiving it with Zenodo:

1. Run the full release workflow successfully in a clean environment.
2. Confirm the final summary table agrees with the values reported in the manuscript.
3. Replace the earlier provisional `cox_rsf_repeated5fold_5repeats.csv` with the newly generated final-standard-package version.
4. Replace the older RSF permutation-importance CSV with the final-RSF output and update manuscript wording if the regenerated values differ.
5. Confirm the bandwidth-sensitivity output matches the archived/locked table.
6. Confirm the manuscript and repository use the same filenames and package versions.
7. Only then tag `v1.0.0` and create the Zenodo archive/DOI.
