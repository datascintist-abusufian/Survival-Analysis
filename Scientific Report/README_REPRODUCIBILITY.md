# Scientific Reports major-revision reproducibility package

## Canonical source data

The revised analysis uses `outcome/uci_echocardiogram_reconstructed_132.csv`, the correctly parsed 132-record UCI Echocardiogram dataset. Survival time is measured in months after myocardial infarction; `event=1` denotes death and `event=0` denotes right censoring/still alive at last follow-up.

## Required scripts

Keep the following files in the same `Scientific Report/` directory:

- `Scientific_Reports_Reanalysis_Master.py` — main entry point/orchestrator
- `Real_Data_Core_Reanalysis.py` — corrected real-data core analysis used by the orchestrator
- `Nested_FP_Cox_Validation_v1.py` — nested FP-Cox validation
- `Synthetic_Augmentation_Experiment.py` — smoothed-bootstrap synthetic-data fidelity/utility experiment
- `Standard_Package_Confirmation_sksurv.py` — final scikit-survival confirmation
- `requirements_reanalysis.txt` — package requirements

## Main entry point

From inside the `Scientific Report/` directory, run:

```bash
python Scientific_Reports_Reanalysis_Master.py --outdir rerun_outputs
```

The script automatically uses:

```text
outcome/uci_echocardiogram_reconstructed_132.csv
```

You can also pass the path explicitly:

```bash
python Scientific_Reports_Reanalysis_Master.py \
  --data outcome/uci_echocardiogram_reconstructed_132.csv \
  --outdir rerun_outputs
```

This runs the corrected real-data core analysis, nested FP-Cox validation, and synthetic-data fidelity/utility experiment.

## Final standard-package confirmation

Install the packages in `requirements_reanalysis.txt`. The final confirmation requires `scikit-survival`.

Then run:

```bash
python Scientific_Reports_Reanalysis_Master.py \
  --data outcome/uci_echocardiogram_reconstructed_132.csv \
  --outdir rerun_outputs \
  --standard-confirmation
```

The confirmation uses `sksurv.metrics.concordance_index_censored`, `brier_score`, and `integrated_brier_score` on the repeated 5-fold cross-validation framework and evaluates performance on held-out real observations.

## Synthetic-data design

Synthetic records are generated by a smoothed multivariate bootstrap fitted within each real training fold. No invented ejection fraction, blood pressure, smoking, cholesterol, or diabetes variables are used. Synthetic observations are not treated as independent patients or external validation data.

## Reproducibility note

The code, reconstructed 132-record source CSV, locked-results ledger, verified output tables/figures, and package requirements should be archived together in the final GitHub/Zenodo release. The earlier 100,000-row synthetic extension is not part of the revised clinical analysis.
